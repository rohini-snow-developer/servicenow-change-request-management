# Project Documentation

## Project Name

ServiceNow Change Request Management System

## Project Objective

The objective of this project is to create a structured Change Request Management System that helps organizations manage IT changes from submission to closure.

## Change Management Process

The system follows a controlled change lifecycle:

New → Assess → Authorize → Scheduled → Implement → Review → Closed

## User Roles

### Requester
Creates and tracks Change Requests.

### Change Manager
Reviews risk and approves or rejects changes.

### Assignment Group
Reviews and implements the assigned change.

### Implementer
Performs the technical implementation.

## Development Components

### Client Script
Performs client-side validation and dynamically manages form fields.

### Business Rule
Performs server-side automation and updates priority based on risk.

### UI Policy
Makes important fields mandatory for high-risk changes.

### Flow Designer
Automates approval, state updates, task creation and notifications.

### GlideRecord
Queries Change Request records from the ServiceNow database.

### Notifications
Keeps requesters and assigned teams informed about important change activities.

## Expected Outcome

The system provides a structured and automated process for managing IT changes while reducing manual work and improving change visibility.
